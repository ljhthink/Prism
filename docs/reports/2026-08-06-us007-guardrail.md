## 2. 安全漏洞扫描（TRAE-security-review）

> 项目为 **BYOK（Bring Your Own Key）客户端**：Provider 端点、请求头、API Key 均由设备所有者本人配置，用于访问其自有的 AI 端点。所有「输入」处于**自配置信任边界内**，无跨信任边界的远程攻击者注入面。以下专项核查在该威胁模型下评估。

### 2.1 输入与边界审计

- **自定义 headers key/value 注入（CRLF）**：`applyCustomHeaders`（第 140-147 行）将用户配置的 key/value 直接传给 Ktor `builder.header(k, v)`。**核实结论：不可利用**。依据：(a) OkHttp 引擎（本项目 `prismApplication` 使用 OkHttp）在**请求构建时**对含 `\r`/`\n` 的头部值抛 `IllegalArgumentException`（RFC 7230 控制字符检查），请求**fail-closed**，不会发出被注入的请求，落入 `catch (e: Exception)` → 通用「网络请求失败」文案；(b) 该输入由设备所有者自配置，无跨信任边界攻击者。**属纵深防御缺口**，建议在编辑器层显式校验（见 §3 S1，LOW）。
- **baseUrl 注入 / SSRF**：`buildEndpoint`（第 117 行）拼接后直接作为目标 URL。**核实结论：不可利用**。(a) 本项目是客户端，非服务端代理，不构成服务端 SSRF（security-review §8.1 排除「仅路径可控」以外，此处 host/协议由设备所有者自配置是其自身意图）；(b) 畸形 URL 由 Ktor/OkHttp 解析失败 → 通用错误文案。**属弱校验**（仅前缀检查），建议强化（见 §3 S2，LOW）。
- **数值/索引边界**：无数组越界、无指针运算、无原生内存操作（JVM 托管语言）。`parseChunkData` 对超大 content（10 万字符）与畸形 JSON 均有测试，不崩溃。✅

### 2.2 执行安全审计（注入 / 最小权限 / 输出编码）

- **代码/表达式注入**：无 `eval`/动态加载，`kotlinx.serialization` 严格类型化反序列化 chunk。`buildRequestBody` 用 `json.encodeToString` 而非字符串拼接。✅
- **SQL/命令注入**：不适用（ObjectBox 对象查询 + 无 shell 调用）。✅
- **单激活状态机**：`ProviderEditSheet` 保存时 `config.copy(..., isActive = false)` 强制关闭激活，再依 `enabled` 走 `viewModel.setActive(savedId)`（Options 第 384-395 行）；独立「激活」按钮（第 403-408 行）也经 `setActive`。**无绕过路径**，BR-concurrency-001 不变式保持。✅（`saveProvider` 兜底 `runInTx` 亦防御直写。）
- **输出编码**：`StreamEvent.Error` 文案为硬编码通用字符串，非反射用户输入，无注入面。✅

### 2.3 密钥与配置安全

- **无硬编码密钥**：扫描全部变更文件，无 API Key / token / 密码明文；`ProviderPresets` 仅含端点与模型名，无密钥。✅
- **API Key 生命周期**：`apiKeyRepository.readApiKeyOnce` 解密密文短暂存于内存即用即弃；`DataStore` 仅存密文（Tink AEAD + Keystore）。`streamChat` 中 `apiKey` 仅拼入 `Authorization` 头，**不落日志、不进入错误文案**。✅
- **错误/日志泄露**：`mapHttpError` 与兜底文案均不含内部路径、异常 detail 或密钥；SSE 错误不携带堆栈。`OpenAICompatibleProvider` 无任何日志输出 → 无密钥泄露风险。✅（CR-05 满足）
- **注意**：`conv`/`settings` 测试用 `RecordingCryptoService` 与 `FakePreferenceDataStore`，仅测试域，不涉生产。✅
- **apiKeyRef 唯一性**：`SettingsViewModel.newCustomProvider` 用 `System.currentTimeMillis()` 生成 `custom-<ts>`，理论上同毫秒内创建两个会碰撞并共享同一 DataStore Key 桶。触发概率极低但违反正则（见 §3 S3，LOW）。

### 2.4 依赖与供应链风险

- `app/build.gradle.kts` 未新增生产依赖；新增 `testImplementation(ktor-server-core/netty/sse)` 仅限测试域，用于真实 SSE 集成测试。Core 依赖（ktor 3.1.3、kotlinx-serialization、okhttp）沿自上轮 ADR-004 审查，非本次引入。✅ 建议在 CI 保留 `dependencies` 扫描门禁（见「自动化建议」）。
