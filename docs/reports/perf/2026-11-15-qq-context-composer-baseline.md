## 1. 被测对象

| 编号 | 方法 | 说明 |
| --- | --- | --- |
| P1 | `QqProactiveComposer.buildReplyUserContext` | **生产形态**：200 条历史 + 480 字正文 + pending 3 条 + 记忆段 + 形状提示 + 时间/间隔 |
| P2 | 同上 | **兼容形态**（`now=null`、无 pending/shape/记忆）：等价于本轮改动前的调用形态，作为相对参照 |
| P3 | `QqReplyBubbles.split` | 480 字、3 段（`---` 分隔） |

夹具：历史每条 ~110 字，每 17 条带一条 `mediaNote`；`incoming` 480 字；P1/P2 各 1000 次采样（预热 200），P3 2000 次采样（预热 500）。

## 3. 门禁判定

| 项 | 阈值 | 结果 | 判定 |
| --- | --- | --- | --- |
| P1 p95 绝对值 | 无既有基线 | 226 µs | **不触发门禁**（相对一次真机生成 5740 ms 为 **0.0039%**） |
| P3 p95 绝对值 | 无既有基线 | 14 µs | **不触发门禁** |
| P1 相对 P2（新增段开销） | >20% 警告 / >50% 失败 | **+151% p95**（90 → 226 µs） | **登记为说明性差异，不判失败** —— 见下 |

**为什么"相对增幅 151%"不判失败**（必须写明理由，不能含糊过去）：

1. P2 不是"改动前的生产基线"，而是**同一函数的降级调用形态**。本轮新增的四个段（`【现在】`+间隔、`pending`、形状提示、末尾提醒）是**新功能**，不是同一功能的劣化；把"多做了四件事"计成回退会得出荒谬结论。
2. 绝对开销 **+136 µs**，而真机一次生成的观测值是 **2207 ms / 5740 ms**（两次 `simulate_inbound`），提示词组装占比 < 0.01%。即便历史拉满 200 条，也不会进入用户的感知阈值。
3. 该函数在 IO/协程侧每轮调用 **1 次**（非热路径循环）。

**结论**：本轮无性能回退；P1/P3 数据作为后续轮次的**初版基线**，下次改动按上表 p95 对比。

## 4. 未覆盖的性能面（如实登记）

- **真机端到端**（网络 + 模型首字 + 3 次 `send_private_msg` + 700 ms×2 气泡间隔）**不在本基线内**；单测只能证明"本地组装不是瓶颈"。真机数据见验收报告 §AC-4。
- `QqConversationStore.append` 的写入侧排序为 **O(n log n)**（n ≤ 200），每轮追加 1–4 条；未单独计时，但 `MAX_PER_CONTACT=200` 决定了上界极小。
- 冷启动（JIT 未预热）首次调用高于 p99，未单独采样。
